# v2.1.3 — security pass

This release addresses the v2.1.2 security review at `b6b5c82`, for a public,
unauthenticated synthetic-data Streamlit demo. FastAPI and the CLI remain local
surfaces. The most realistic public risk was a crafted note consuming the shared
server with repeated regex scans; large evidence projections and Markdown
quotations also made review less reliable. Engine version is **2.1.3**.

| Finding | Fix | Exploitable surface |
| --- | --- | --- |
| F1: extraction CPU and evidence amplification | Indexed sentence/subject boundaries, one AHI missingness-token scan, non-overlapping clause search; bounded requests and evidence | Public demo; local API/CLI |
| F2: Markdown and letter structure injection | User quotations, specialty, names, warnings and errors render as literal text; letter identity/header fields collapse controls/newlines, and quotations escape controls inside delimiters | Public demo; exported letters |
| F3: long numeric tokens and exposed extraction exceptions | Reject numeric tokens longer than six digits with controlled validation errors; minimize Streamlit error details | Public demo; local API/CLI |
| F4: snapshot path traversal | Strict lowercase source slugs and resolved-path containment of latest/history/diff/log paths, including symlinks | Local policy monitor / crafted registry or filesystem |
| F5: unbounded policy downloads | Stream decompressed content with a 2 MiB limit, a 15-second overall deadline and at most three redirects; verified TLS and no HTTPS downgrade | Local policy monitor |
| F6: vulnerable pytest | Upgrade to pytest 9.0.3 | Development / CI supply chain |
| F7: vulnerable requests and mutable actions | Upgrade requests to 2.34.2; pin both GitHub Actions to reviewed commit SHAs; workflow permissions `contents: read` | Supply chain |
| F8: unbounded dependency resolution | Universal transitive lock with exact pins and hashes, consumed by deployment, devcontainer, Makefile and CI; CVE audit fails for new unignored findings | Deployment / supply chain |

Input limits are 20,000 note characters, 50 correction events and 10 document
review proposal spans. The API rejects bodies above 1 MiB before JSON decoding,
including chunked requests. Validation is shared across Streamlit, API and CLI.
Every fact retains at most 10 evidence spans and reports the exact total when
truncated, including reviewer views, letters and exports. Original proposal
counts participate in canonical archive validation; corrections update effective
counts. No corpus or existing golden has more than 10 spans per fact.

The note indexes exist only within an operation and are released afterward; they
are not shared session caches. Existing immutable bundle/resource caching remains
separate from user notes.

## Exact output equivalence

Frozen test-only copies of the v2.1.2 extraction and citation-context functions
come from `b6b5c82`. Only the extractor's schemas import is relocated. The test
compares canonical UTF-8 bytes for facts, states, spans, full citation context,
requirement results and overall status on **672 cases**: 52 corpus cases,
20 independent regressions and 600 seeded generated notes. Generated notes mix
corpus vocabulary, triggers, punctuation, tabs, spaces, Unicode and newlines at
sizes where the old oracle runs quickly.

One previously identified difference was fixed: the conservative-therapy span
in `SAFETY-01-cross-therapy-linkage` ends at **161**, excluding the comma. The final
672-case differential has **zero differences**. The deliberately new rejection
limits and capped evidence output have separate security tests. Stdlib `bisect`
and the internal `note_context` module are explicitly added to the deterministic
extractor import allowlist, with explanatory comments.

## F1 measurements

Single-process wall times on Python 3.12.3, same machine, frozen v2.1.2 versus
v2.1.3. Old calls exceeding eight seconds were terminated. These are illustrative
measurements, not latency guarantees.

| Crafted input | Before | After |
| --- | ---: | ---: |
| `"ahi " * 800` | >8 s | 2.12 ms |
| `"nsaids " + " " * 3200 + "z"` | >8 s | 3.48 ms |
| `"no " * 8000` (24,000 characters) | 2.056 s | Controlled length rejection, <0.01 ms |
| `"PT for 6 weeks. " * 2000` (32,000 characters) | 4.488 s | Controlled length rejection, <0.01 ms |
| `"osa " * 500` | 72.14 ms | 6.51 ms |

The 500-OSA exported review JSON decreases from **1,161,313 to 43,886 bytes**,
retaining 10 spans and displaying the total of 500. Regression tests isolate the
AHI and whitespace cases in subprocesses with generous two-second deadlines;
over-limit rejection must finish within half a second and the OSA projection
must remain under 100 KB. A 4,400-digit duration produces a controlled error with
no traceback. Link and image payloads remain literal in the Streamlit review.
Monitor tests cover oversized content, redirect loops and an incomplete chunk
trickling beyond the overall deadline. Snapshot tests cover `../outside` and
symlinks escaping the root.

## Dependency audit and deployment

`requirements.in` records direct dependency choices; `requirements.lock` is the
hashed universal resolution. Regenerate deliberately with
`uv pip compile requirements.in --universal --generate-hashes --output-file requirements.lock`.
`requirements.txt` includes that lock for Streamlit Cloud. Local and CI installs
use `pip install --require-hashes -r requirements.lock`. The lock includes
**Tornado 6.5.10**, newer than the patched minimum 6.5.9. Streamlit explicitly
uses Tornado (`server.useStarlette = false`).

CI runs `python scripts/audit_dependencies.py` with pip-audit 2.10.1 against the
lock. The audit passed with no unignored vulnerabilities. Its only exceptions
are the seven Starlette CVEs recorded in
[security/pip-audit-ignores.json](../../security/pip-audit-ignores.json), each with
a specific one-line unreachability reason: no multipart/form endpoints,
FileResponse/StaticFiles, unconstrained HTTPEndpoint, or URL/hostname security
middleware in the local API. Alias reports account for 14 ignored audit entries.
New unignored CVEs fail CI. Reassess these exceptions before adding API features
or deploying that API publicly.

Accepted scope decisions remain: no authentication for the synthetic public
demo; reviewer/editor identity is self-reported; archive hashes can be recomputed
by someone controlling a local database and do not provide authenticated
provenance; the unreachable local-only Starlette CVEs are explicitly excepted.
Do not paste real patient information. Downloads intentionally include the
submitted synthetic note and its review/audit data. Public-host logging and live
host configuration are not independently verified by these local tests.

## Validation and release state

Both report one upstream Starlette TestClient/AnyIO deprecation warning.

READY results. Conformance checks all 624 facts: **163 captured, 446 missing,
15 needing review**, zero violations. Both full suites include the differential
and security regressions.

Six evaluation goldens and six generated artifacts change only engine/app
version fields from 2.1.2 to 2.1.3. All facts, states, spans, statuses,
fingerprints and governance outputs remain identical. The corpus and the
20 independent fixture files are unchanged.

The branch is proposed for review; do not merge as part of this security pass.
The owner must reboot the Streamlit host after an eventual merge to main, as
required by the [deployment checklist](../testing.md). In-place code updates
cannot establish that every loaded module or dependency is current. Live
v2.1.3 deployment is not yet verified.
