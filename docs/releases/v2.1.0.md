# v2.1.0 — extraction safety, citation context and performance

Prepared October 7, 2026; independent-check second pass October 8, 2026, on `v2.1` from main `fd76248` (v2.0.0).
This is release preparation only: no merge or tag. Engine version is `2.1.0`;
canonical record `schema_version` stays `2.0.0`.

## Behavior

Evaluation binds one immutable bundle snapshot containing runtime rules,
provenance, policy sources, manifest and every referenced release file. Parsed
bundles and computed rulebook status are cached by digest with bounded caches.
The initial digest is computed once and reused throughout evaluation; the final
digest is recomputed to reject a mid-evaluation change for retry. Changes to
runtime or release files invalidate the cache on the next evaluation. Each cold
bundle file is parsed once; an unchanged warm evaluation does not parse YAML or
recompute rulebook status. Snapshot freshness and the governance clock remain live.

Streamlit fact verification and correction controls display containing sentences
with each citation marked `⟦…⟧`; correction occurrence selection also displays
context. API and CLI result output expose a derived `citation_context` map.
Canonical archive records and acceptance fixtures omit this field; reviewer
report exports and Streamlit downloads include it. A reader verifies and discards
it when consuming a review projection. No citation-context text enters facts,
spans, original snapshots or fingerprints. Decimal points inside numbers do not
end a context sentence; semicolons do not either. Only period, question mark,
exclamation mark, or newline ends context. A citation crossing sentences displays all of them.

The reproduced contrast now displays:

> ⟦NSAIDs for 8 weeks with no improvement in sleep⟧ but significant improvement in pain.

Exclusion and review triggers now examine the entire candidate sentence rather
than requiring adjacency. Exclusions cover ruled out, ordered, prescribed,
recommended, not yet started, has not started, not completed, never completed,
and cancelled/canceled. OSA ruled-out language excludes the diagnosis; it does
not erase a completed PSG mentioned in that sentence. Completion exclusions
apply to therapy/study candidates; other qualifying clinical findings route to
review. Review triggers cover resolved, history of, prior episode, and previous
episode. Contrast checks include semicolon clauses with or without an explicit
contrast marker. Narrow finding attribute scope remains unchanged.

Four of the original five wrong-capture inputs now meet the reviewer expectation;
case 12 remains. Primary scalar outcomes are now **18 correct, 1 wrong capture,
1 false refusal**. Case 2's secondary analgesic-duration refusal and case 17's
citation error also remain. These are observed outcomes on the same selected
notes after development, not a fresh accuracy estimate.

All **20 unchanged inputs are named regressions** in
`test/fixtures/v210_independent.json` and `test/test_v210_independent.py`, with
reviewer-correct scalar values, states, requirement statuses and overall status.
Four additional **strict xfails assert correct expectations**: case 12 review,
case 17's citation of the completed-study sentence, case 18's normal intact
reflexes (false), and case 2's generic analgesic duration (8 weeks). Every other
independent assertion passes. Case 2's current-relief citation is a passing
regression. The inputs are now regressions and **no longer a held-out measure**.
These patterns are handled; every failure class remains open.

## Performance and validation

Python **3.12.3**, same local environment, one `MRI-01-complete` evaluation per
cold/warm observation. YAML and rulebook-status calls are instrumented with
wrapping mocks; these are measurements, not timing assertions. Use
`python -m scripts.benchmark_evaluation` to reproduce evaluation measurements,
and `python -m pytest -q` for suite time. A pristine `git archive main` checkout
is also measured to keep the baseline independent of edits.

| Measurement | v2.0.0 before | v2.1.0 after |
| --- | --- | --- |
| One cold evaluation | 0.450878 s | 0.054871 s |
| One warm evaluation | 0.452958 s | 0.006025 s |
| YAML loads, cold / warm | 289 / 289 | 25 / 0 |
| Rulebook-status computations, cold / warm | 10 / 10 | 1 / 0 |
| Full suite, original baseline / first pass | 359.36 s; 760 passed | 29.17 s; 798 passed, 7 strict xfails |
| Independent pristine-main suite confirmation | 363.69 s; 760 passed | Same first-pass run above |

An independent pristine-main evaluation repeat measured 0.505941 s cold and
0.521621 s warm, with the same 289 YAML / 10 status calls. The initial pre-edit
observations remain the comparison baseline. Cache warmth, concurrent machine
activity and instrumentation affect elapsed time; call counts are deterministic.

Second-pass validation (Python 3.12.3): **861 passed, 11 strict xfails in
28.88 s**, with Ruff lint/format and whitespace checks passing. A fresh
instrumented cold evaluation took **0.049131 s**, warm
**0.005557 s**; YAML loads remain **25 / 0** and rulebook-status
computations **1 / 0**. These elapsed times are observations, not assertions.

The labeled synthetic corpus is **52/52 exact statuses**, with **no corpus fact,
requirement-status or overall-status changes**: 7 PENDING_VERIFICATION, 3 NOT_READY,
30 CANNOT_DETERMINE, 12 NEEDS_REVIEW. No case moves toward MET or READY.
Conformance remains **163 captured, 446 missing, 15 review, zero nonconforming**
across 624 fact states. Corpus inputs were not changed.

All existing API rule-reload/old-attestation rejection, mid-evaluation-change and
Streamlit cache-clearing tests pass unchanged. New tests cover next-evaluation
reloads, release-only digest changes, immutable cached content, zero warm YAML
loads/status computations, full contrast context, API/CLI context consistency,
Streamlit verification/correction context, and preserved schema round trips.
Ruff lint/format and `git diff --check` pass. Historical artifact/golden generation
uses `2026-09-01T00:00:00Z`, matching CI.
