## Policy fetch and pre-demo procedure (M2, PR #11)

The bounded httpx fetch retains the v2.1.2 requests decoding semantics. Aetna
sent `text/html` without a charset during verification: requests selected
ISO-8859-1, while the rewritten path selected UTF-8. Decoding those bytes
differently changed normalized policy text. The current path uses requests'
header-based encoding and `Response.text` fallback on the downloaded bytes.
The 2 MiB byte cap, overall deadline, redirect limit, HTTPS-downgrade refusal,
TLS verification, and refusal of URL credentials remain in place.

Before a demo, follow the [testing procedure](../testing.md):

1. Run `python -m engine.policy_monitor --check` without writing. Confirm
   status `OK` and `new_hash == old_hash`.
2. Only after that successful read-only check, run
   `python -m engine.policy_monitor --check --write` to record its check time.

If a hash changes, do not write; request human policy review. Do not replace a
baseline or hash to force agreement. Drift remains unresolvable by design in
this prototype; monitoring does not promote a policy or modify a rulebook.

## Type-aware consistency (M1, PR #12)

Canonical JSON comparisons again distinguish `true`, `1`, and `1.0` across
evaluation results, corrections, reports, and archive validation. The helper
duck-types callable `model_dump(mode="json")`, recurses through containers,
sorts keys, and rejects non-finite JSON numbers. Comparing the serialization
also tolerates models loaded through different engine module instances.
The comparison fields, check order, and validation messages are unchanged.
Typed numeric fields may still normalize through Pydantic before comparison.

## Conservative extraction cues (H1(a), PR #13)

The shared finding path routes the following copied-note, persistence, and
template cues to `NEEDS_REVIEW`. Matching is case-insensitive; these are the
exact added regular expressions from `engine/extract.py` (adjacent Python
string literals concatenate):

```python
PERSISTENCE_REVIEW_TRIGGER = (
    r"\bno\s+longer\b(?:(?!\bno\s+longer\b).)*?\b(?:present|has|have|reports|noted|seen|evident|active)\b"
    r"|\b[\w/-]+\s+no\s+longer\b(?!\s+than\b)"
)
COPIED_NOTE_REVIEW_TRIGGER = (
    r"\b(?:(?:previous|prior)\s+note|copied[\s-]+(?:from|forward)|carried[\s-]+forward|"
    r"from\s+(?:the\s+)?(?:prior|previous)\s+(?:note|visit|encounter)|"
    r"per\s+(?:the\s+)?(?:prior|previous)\s+(?:note|visit)|"
    r"(?:note|visit|encounter)\s+(?:dated|from)\s+"
    r"(?:\d{4}(?:[-/]\d{1,2}(?:[-/]\d{1,2})?)?|\d{1,2}[-/](?:\d{4}|\d{1,2}[-/]\d{2,4})))\b"
)
CHECKBOX_REVIEW_TRIGGER = r"\[\s+\]|\[x\]|[☐☑☒]"
```

Examples include `previous note`, `prior note`, `copied from`,
`copied-forward`, `carried forward`, `from the prior encounter`,
`per the previous visit`, `note dated 2019`, `visit from 2021-03-09`, and
`encounter dated 03/09/2021`. Persistence examples include `no longer present`,
`no longer has`, and `radiculopathy no longer`; `no longer than` is excluded
from the second persistence alternative. Checkbox cues include `[ ]`, `[x]`,
`[X]`, `☐`, `☑`, and `☒`, including whitespace inside an empty checkbox.

Copied-note and persistence cues use the containing sentence. Checkbox cues
must precede the finding within that sentence. Periods, question marks,
exclamation marks, and newlines delimit sentences; semicolons and decimal
points between digits do not. Existing `resolved`, `history of`, `prior episode`,
and `previous episode` review cues remain. These finite patterns do not
interpret general provenance or reconcile a clinical episode.

## Attestation context (H1(b), PR #14)

Streamlit attestation and original/effective correction citation lists show
the containing sentence plus up to one neighbouring sentence on each side.
The original note is expanded by default. Note content uses literal `st.text`,
and every attestation checkbox is preceded by:
“Context shown is an aid; read the full note before attesting.”
The occurrence picker and API/CLI `citation_context` retain their existing
containing-sentence representation.

In this release, a left cut is prefixed with `[truncated]…` and a right cut is
suffixed with `…[truncated]`; only sides actually cut receive markers. The
1,000-character cap includes both markers and the complete marked citation.
If those cannot fit, the UI shows a literal notice directing the reviewer to
the expanded full note. This display change does not alter extraction,
statuses, fingerprints, letters, archive contents, or the readiness gate.

## Remaining false-READY paths

Reviewers can still attest without reading, and reviewer identity remains
self-reported. The following examples remain open limitations:

- **Phrasing outside the list:** `Prior visit note (2019): low back pain with
  radiculopathy, right L5 distribution strength 4/5, NSAIDs for 8 weeks with no
  improvement. Today: asymptomatic.` still produces all four lumbar facts as
  `MET`. With governance at `2026-09-01T00:00:00Z` and four attestations, it
  reaches `READY`, `submission_readiness=true`, and `policy_trust_level=verified`.
  The attestation window exposes the contradiction without changing that result.
- **Distant contradictions:** in `Low back pain with radiculopathy. Visit
  logistics discussed. Today: asymptomatic.`, the last sentence is more than
  one neighbour from the diagnosis citation and may be outside its window.
- **Cross-sentence temporality:** `Copied from 2019 visit. Low back pain with
  radiculopathy. Right L5 distribution: strength 4/5. NSAIDs for 8 weeks with no
  improvement.` does not carry the first sentence's provenance into later
  findings. Likewise, an episode described as resolved in a following sentence
  needs interpretation across sentences.
- **Laterality/attribution:** `Low back pain with left leg radiculopathy.
  Exam: right L5 distribution strength 4/5 from prior hip surgery. NSAIDs for
  8 weeks with no improvement.` can combine the left-sided complaint with an
  unrelated right-sided finding. Attestations can still yield a ready result.

The window can also omit context at its character cap. Full-note review and
human policy review remain necessary. A ready result is an administrative
prototype state, not evidence of extraction accuracy or medical necessity.
