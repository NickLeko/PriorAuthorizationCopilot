# v2.1.1 — deployment safety

The live Streamlit demo failed with a redacted Pydantic validation error for
both the contrast-clause note and a bundled case. The traceback pointed to the
v2.0 service constructor's line number while displaying v2.1 source. A cached
service from the prior release surviving deployment is the inferred cause;
the unredacted deployment logs were unavailable, so it is not confirmed.
Clean Python 3.13.12 browser and AppTest runs with the pinned requirements passed.

The Streamlit service factory now keys its resource cache on engine version
and the current bundle digest. A release or bundle change creates a fresh
service. Bundle hashing reads current bytes on each rerun and reuses cached
manifest parsing. Engine version is 2.1.1. CI checks Python 3.12.3 and 3.13.

The exact-note AppTest checks NEEDS_REVIEW, both review views, original and
effective citation context, quotation-occurrence context, and exceptions after
each rerun. A cache regression checks reuse within a version and replacement
when the version changes. Extraction behavior and its open failure classes are
unchanged. This patch does not establish that the live deployment has recovered;
a cold deployment and live verification remain necessary.

Validation: Python 3.12.3 and 3.13.12 each passed 862 tests with 11 strict
expected failures. The labeled corpus remained 52/52; conformance recorded
163 captured, 446 missing and 15 review facts with zero violations. Ruff
passed. The six generated artifacts and six evaluation goldens changed only
their engine/app version fields from 2.1.0 to 2.1.1; decisions, evidence,
fingerprints and governance outputs did not change.
