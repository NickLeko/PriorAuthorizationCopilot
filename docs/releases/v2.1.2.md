# v2.1.2 — mixed-module validation and restart guard

The deployment log confirmed that the host pulls code into the running app and
reruns `app.py` without restarting the process. It deployed branch `main` and
root `app.py`; the issue was not a confirmed wrong-branch deployment. Old and
new engine module loads can coexist, including Pydantic model classes with the
same names but different identities. Their model-object equality is false even
when their dumped field values are identical. The original failure was the
`EvaluationResult` consistency check: "Metrics disagree with validated
requirement results." An isolated retained-service/module-replacement experiment
reproduced that exact error; a fresh service passed.

v2.1.1 keyed the Streamlit resource factory on engine version and bundle digest
and added Python 3.13 CI and stronger review-view tests. It addressed resource
cache reuse but did not make validation independent of loaded model identity,
or detect an imported engine version that lagged the on-disk release marker.
It did not guarantee a process restart or establish live deployment recovery
on v2.1.1; subsequent fresh exports still reported engine 2.1.0.

v2.1.2 compares `model_dump()` values in validation, including metrics, nested
evidence, policy, result, blocker and verification copies. Archive policy checks
and the service's runtime-policy comparison also use dumped values. Different
values remain rejected. The mixed-module regression retains a service while
replacing engine modules, then checks both MRI-01-complete and the contrast
note; it also checks that changed metric values still fail validation.

On every Streamlit run, the app reads the version literal from
`engine/__init__.py` on disk without executing it and compares it with loaded
`engine.__version__`. A mismatch displays "App code was updated; the server
needs a restart" and stops before importing engine submodules, constructing a
service or running evaluations. An unreadable or invalid release marker also
stops the app. AppTest checks the guard on reruns and fresh sessions.

The owner release checklist remains in [testing.md](../testing.md). Every push
to main, including docs-only pushes, requires a reboot because this host updates
in place. A matching version marker is not proof that every module is current;
same-version edits still require that owner step. Engine version is 2.1.2.
Extraction behavior and its open failure classes are unchanged. This PR remains
unmerged and untagged; live v2.1.2 behavior has not been verified.

Validation: Python 3.12.3 and 3.13.12 each passed 864 tests with 11 strict
expected failures. Both versions retained 52/52 exact corpus statuses and
conformance of 163 captured, 446 missing and 15 review facts with zero
violations. Ruff passed. Six generated artifacts and six evaluation goldens
changed only engine/app version fields from 2.1.1 to 2.1.2; decisions, evidence,
fingerprints and governance outputs are unchanged.
